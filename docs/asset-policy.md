# Asset policy (rule #1)

**Nothing from the game is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: data sections, strings, tables,
  resources, code beyond the signatures below;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, screenshots.

## Allowed

* our own code that understands formats;
* build identities: BLAKE3 of an executable, CodeView GUID/age;
* per-build offsets of functions we hook, under names we choose;
* byte-pattern signatures that locate functions or data in the executable;
* small interoperability constants (magic numbers, enum values) we write;
* synthetic test data generated by our own code.

## The exceptions

Four files, each entered in `xtask/src/policy.rs` with its reason:

* `crates/victory-formats/src/bcpack-tables.bin` (about 78 KB): the constant
  tables of the BCPack format (entropy models, index rank tables, control
  codes, per-format dictionaries). A BCPack stream cannot be decoded without
  exactly these tables and they cannot be derived, so they ship with VIctory
  by the project owner's decision (2026-11-23). They are part of the format,
  not our work, and the repository's licence does not cover them.
* `crates/victory-dxil/shaders/tri_vs.dxil` and `tri_ps.dxil` (3 KB each): our
  own triangle, compiled from `tri.hlsl` beside them,
  `dxc -T vs_6_0 -E vs_main -Fo tri_vs.dxil tri.hlsl` and the same with
  `ps_6_0`/`ps_main`. They are what the translator is tested against and the
  pair the Android host translates on the device, so they have to be bytes
  rather than source; they contain nothing from any title.
  SHA-256 `1162fb90adbd8e7e5bbd445b7728cbd18efca7fff063b161d385826c0a88b1fe`
  (vertex) and
  `f70e54c88f5849563c17cdbb074cf2bf9d09f12965145985b1f08d7122fb6ab0`
  (pixel).
* `android/gradle/wrapper/gradle-wrapper.jar` (43 KB): Gradle's own bootstrap,
  so `./gradlew assembleDebug` works in a fresh clone without a system Gradle.
  SHA-256 `7d3a4ac4de1c32b59bc6a4eb8ecb8e612ccd0cf1ae1e99f66902da64df296172`.
  It is third-party tooling rather than data, it is the only jar in the tree,
  and a changed hash means someone replaced it.

Nothing else of this kind is accepted.

## Where data lives

Outside the repository, configured in `victory.toml`: `game_dir` (the
user's dump), `test_titles`, and `cache_dir` for everything derived
(default `%LOCALAPPDATA%\victory\cache`).

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist: files must have an allowed
   type, be under 640 KiB, contain no binary data or known binary
   signatures, and hold no long hex/base64 runs. Exceptions need an entry
   with a reason in `xtask/src/policy.rs`.
3. At runtime, everything that writes derived data calls
   `victory_core::ensure_outside_repo`.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

## If something slips through

A follow-up commit is not enough. Rewrite history
(`git filter-repo --path <file> --invert-paths`), force-push, and have
everyone re-clone.
